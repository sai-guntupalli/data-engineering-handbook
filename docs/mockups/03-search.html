Apache SparkSpark tuning

Partition pruning in Spark SQL

When a table is partitioned by a column and your query filters on it, Spark skips the directories that cannot match. Partition pruning turns a full scan into a read of only the folders you need.

spark.read.parquet("data/orders/")
  .filter("order_date = '2026-11-01'")
  .explain()
# PartitionFilters: [order_date = 2026-11-01]

Apache IcebergPartitioning

Hidden partitioning

Iceberg records partition transforms such as days(ts) in table metadata, so readers get partition pruning without having to filter on a separate partition column.

CREATE TABLE lake.orders (id bigint, ts timestamp)
USING iceberg
PARTITIONED BY (days(ts))

ParquetPredicate pushdown

Row-group pruning with statistics

Each row group stores min and max values per column. A reader compares your filter against them and skips row groups that cannot match, which is pruning one level below partitions.

pq.ParquetFile("orders.parquet").metadata.row_group(0)
  .column(3).statistics   # min, max, null_count

BigQueryCost control

Require a partition filter

Setting require_partition_filter makes BigQuery reject queries that would scan every partition, so an unfiltered query fails fast instead of billing a full scan.

ALTER TABLE shop.orders
SET OPTIONS (require_partition_filter = TRUE);
